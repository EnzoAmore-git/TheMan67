Это лабораторный замер, не полевые Core Web Vitals. INP на 75-м перцентиле не измерялся; TBT не объявляется его заменой.

В локальный HTTP-трафик установленное защитное ПО добавило собственный блокирующий скрипт около 184 КБ с адреса gc.kis.v2.scr.kaspersky-labs.com. Он присутствует в отчётах Lighthouse, но отсутствует в исходниках сайта. Best Practices фиксирует небезопасный HTTP-запрос; точный вклад защитного ПО в каждый балл не изолирован. Настройки защиты не менялись. После публикации на HTTPS нужен повторный замер в чистом профиле. Мобильный ориентир 90+ в текущем измерении не достигнут.

Исправления по первому замеру: повышен приоритет image preload, сокращены дубли @font-face, добавлена ранняя загрузка основных шрифтов, исправлены доступные имена строк прайса, production CSS объединён в один файл. Повторные замеры показали колебание Mobile Performance 83–88; приведён последний результат, а не лучший.

## Ограничения

- Не выполнялись испытания на реальном iOS Safari, Android и Firefox.
- Системная настройка reduced motion и отключение JavaScript отдельно в браузере не переключались; поддержка проверена по CSS/JS и структуре ссылок.
- Свайп реализован, но физическое сенсорное устройство не тестировалось.
- Внешние страницы мессенджеров могут требовать приложение/авторизацию; отправка сообщений не относится к smoke-проверке.
- Production-домен не обновлялся. DNS, Beget, HTTPS, gzip/brotli и Cache-Control требуют проверки на целевом хостинге.
- Подтверждение цен, расписания, условий скидки и отсутствующих дипломов остаётся за владельцем бизнеса.

## Повторить вручную

1. npm run check, npm run build, npm run preview.
2. На каждой контрольной ширине пройти от hero до footer; проверить запись и полный адрес.
3. На телефоне открыть меню, перейти к прайсу, открыть фото, сменить фото и закрыть просмотр.
4. Клавиатурой пройти ссылки и dialog; убедиться, что фокус виден и после Escape возвращается на фото.
5. Включить reduced motion и проверить отсутствие анимаций; выключить JS и проверить навигацию, запись и ссылки фотографий.
6. Lighthouse на HTTPS после реальной публикации; не сравнивать лабораторные цифры с полевыми данными напрямую.
